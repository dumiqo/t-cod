# 29. Проверка по контракту

Проверка готового кода целиком: контракт, сиды, инварианты под нагрузкой, скорость и поведение
без Redis. Тесты пишутся на готовый код, поэтому красная фаза — временная поломка реализации
(`CLAUDE.md`); найденная ошибка — тест-воспроизведение и исправление в той подзадаче, где
нашлась.

Разбита на подзадачи 29.1–29.5, каждая — свой коммит и своя строка статуса, порядок по номерам.
29.1–29.3 и 29.5 — в `dotnet test`; 29.4 — ручной прогон k6 на реальном процессе, итог
в заметках, использует проверку инвариантов из 29.3. 29.5 — две проверки отказных режимов,
в том числе восстановление после остановки Redis, перенесённое в критерии 29.4.
