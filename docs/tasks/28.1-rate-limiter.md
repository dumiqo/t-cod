# 28.1 Ограничитель

Статус: готово (bf995db)

Решения проработки — в [задаче 28](28-rate-limit.md#проработка): метка `RateLimitedAttribute`,
`RateLimitMiddleware`, скрипт строкой с `KEYS` / `ARGV`, `ClientErrorMapping[429]`.

- окно и хранение счётчика по решению задачи 27; место в конвейере, ключ, `429` — в [задаче 28](28-rate-limit.md);
- первый тест — префиксует ли `WithKeyPrefix` ключи Lua-скрипта: иначе тесты делят счётчик;
- 60-й запрос проходит, 61-й — `429` по контракту; граница с обеих сторон: 60 запросов в `T`,
  в `T + 59,999 с` — `429`, в `T + 60,000 с` — проходит; окно скользящее — серия через границу
  минуты часов тоже получает `429`; счётчики разных пользователей не смешиваются;
- `429` в журнал не попадают: после серии отказов запрос в момент выхода старейшего из окна
  проходит; `Retry-After` — точное значение с округлением вверх;
- запросы в одну миллисекунду не схлопываются: 60 запросов при стоящих часах — все проходят;
- запросы без пользователя не считаются; эндпоинты вне лимита — тест, в том числе
  `HarnessController`, несуществующий маршрут и `405`;
- считаются ли `400`, `403` и `404` — по решению задачи 2, тест на каждый;
- атомарность счётчика: 70 одновременных запросов одного пользователя — ровно 60 не-`429`;
- `429` — событие 1003 с точными `userId` и `retryAfter` и `club.requests.rejected` с тегами
  `rate-limit` / `too-many-requests`; тело — точные `status`, `title`, `traceId`, совпадающий
  с `TraceId` события, и нет `reason`; `type` — `https://tools.ietf.org/html/rfc6585#section-4`,
  `title` — `Too Many Requests`, content-type — `application/problem+json`;
- `429` на каждом из восьми эндпоинтов — DataRow по маршрутам: 60 запросов «сжигаются»
  `GET /enrollments/{несуществующий}` (`404`, считается), 61-й на проверяемый эндпоинт — `429`.
  У пишущих (§1, §2, §3, §7, §8) отказ без следов: места, остаток посещений, бронь, очередь
  не изменились, ключ идемпотентности не сохранён, событий и счётчиков успеха нет;
- порядок кодов: 61-й с битым телом — `429`, а не `400`; 61-й от не-админа на §6 — `429`,
  а не `403`;
- после реализации — полный прогон: существующий тест, упавший на `429`, не правится,
  а обсуждается.

Найдено при реализации:

- без «стража» лимитер ронял `500` тесты отказа Redis из 26.4 (они уже были): 28.1 и 28.2
  сделаны одним коммитом, 28.2 — своими тестами до кода (по решению пользователя);
- префикс `WithKeyPrefix` действует на `keys[]` скрипта: журнал лежит
  в `{префикс}rate:{userId}`, без префикса ключа нет;
- полный прогон после реализации: ни один существующий тест в `429` не упёрся.
