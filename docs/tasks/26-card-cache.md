# 26. Кэш карточки

С поведением при отказе Redis по итогам задачи 24. Какие операции сбрасывают кэш и как —
по решению задачи 25.

Тест на гонку заполнения и сброса из задачи 25: обёртка над `ICacheService` задерживает
`SetAsync` чтения, пока не закоммитится отмена; после этого карточка показывает `cancelled`.

Разбита на подзадачи 26.1–26.2, каждая — свой коммит и своя строка статуса, порядок по номерам.
26.1 зависит только от задачи 25, 26.2 — от задачи 24: исследование отказа Redis не держит
сам кэш.

## 26.1 Кэш и сброс

- что кэшируется, ключ с проверкой владельца, кэшировать ли `404` — по решению задачи 25;
  чужая карточка из кэша не отдаётся, вместо неё `404`;
- каждая операция из задачи 25 сбрасывает кэш так, что следующий запрос карточки видит
  её результат;
- тест на гонку заполнения и сброса (выше);
- тест, что кэш используется: без него все тесты выше зелёные и без кэша. Изменить бронь в базе
  мимо API — карточка отдаёт прежнее значение (контракт это разрешает);
- TTL в Redis идёт по реальному времени, фейковые часы его не двигают: если от TTL зависит
  поведение, тест на него — не переводом `app.Clock`;
- промах `RedisCacheService.GetAsync` для значимых типов — своим методом рядом с выданным.

## 26.2 Кэш при отказе Redis

- поведение по решению задачи 24: при упавшем Redis карточка читается из базы, а не `500`;
  сброс кэша при упавшем Redis не ломает операцию;
- события и счётчики отказа Redis — по схеме задачи 6;
- если решение задачи 24 даёт общую обёртку над Redis для кэша и ограничения частоты, она
  делается здесь, а 28.2 её использует.
