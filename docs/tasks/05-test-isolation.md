# 5. Исследование: изоляция тестов

Статус: готово (6775d70)

Варианты: свои данные на тест в общей базе; своя база на тест (есть `ScratchDatabase`);
Testcontainers.

Известно:

- обвязка из задания читает `TEST_POSTGRES` и `TEST_REDIS` — похоже, проверяющие подставляют
  свои сервисы, и Docker в их окружении может быть недоступен;
- `README` говорит, что тестам нужны Postgres и Redis из `docker compose`;
- решение должно запускаться командами из `README` без дополнительных шагов;
- лимит 60 запросов в минуту считается на пользователя;
- при своей базе на тест Redis остаётся общим, а id пользователей в разных базах совпадают:
  без префикса ключей пересекутся счётчики лимита и кэш карточек;
- после задачи 28 тесты одного пользователя упрутся в `429`. Решить сразу, чтобы не переписывать
  тесты потом: свой пользователь на тест или лимит из настроек;
- сиды отсчитаны от реального момента первого запуска (`DateTime.UtcNow` в сидере): тест на сидах
  с фиксированными часами разойдётся с «занятием через 20 минут»;
- тест гонки по решению задачи 4 держит замок занятия на своём соединении и ждёт, пока запросы
  встанут в ожидание. Считать их по цепочке `pg_blocking_pids` от своего соединения
  (рекурсивный запрос к `pg_stat_activity`): прямо за ним ждёт только первый запрос, остальные —
  за первым. Так считаются ровно запросы, вставшие за замком теста, что бы ещё ни ждало в базе,
  например транзакция, которую оставил висеть предыдущий тест. Тесты сейчас идут по одному
  (`[Parallelize]` и `.runsettings` нет). Проверено под суперпользователем `club`; под другой
  ролью (`TEST_POSTGRES`) видимость чужих сессий не проверена — приложение и тест должны
  подключаться одной ролью.

Решение — в заметках, раздел «Изоляция тестов». Как ведут себя JwtBearer при подменённом
`TimeProvider`, клон базы и старт хоста, проверено отдельной программой. Что учесть в коде —
записано в задачи 7, 8, 27 и 28.
