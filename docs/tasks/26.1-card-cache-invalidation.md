# 26.1 Кэш и сброс

По решению задачи 25 (заметки, раздел «Кэш карточки»).

- миграция `passes.version bigint NOT NULL DEFAULT 0`; карточка читает `version` тем же
  SELECT;
- версию поднимают в своей транзакции §1, §2 при изменении мест, §3 при настоящей отмене
  (и меньше чем за 2 часа, когда остаток не меняется) — автору, продвижение — продвинутому.
  Тест на каждую операцию и на каждый случай «не поднимает»: отказ `409`, повтор §1 по ключу,
  §2 с тем же числом мест, повтор §3, §7, §8, пропуск при продвижении;
- `CardCache` над `IConnectionMultiplexer`: чтение поля `{id}` из `card:{userId}`, заполнение
  Lua-скриптом (версии нет или старше — замена hash, равна — добавление поля, новее — ничего),
  надгробие после коммита (версии нет или старше — hash `{v: новая}`). Первым делом проверить,
  что `WithKeyPrefix` префиксует ключи скрипта, — иначе тесты разных `TestApp` делят ключи;
- чужая карточка из кэша не отдаётся, вместо неё `404`; `404` не кэшируется — тест, что после
  продвижения карточка по id записи в очереди отдаёт бронь;
- каждая операция сбрасывает кэш так, что следующий запрос карточки видит её результат, в том
  числе в других карточках того же пользователя (остаток абонемента) и у продвинутого;
- тест на гонку заполнения и сброса (в [задаче 26](26-card-cache.md)): задерживается скрипт
  заполнения, а не `ICacheService.SetAsync`;
- `Cache:CardTtl`, по умолчанию 5 минут, проверка при старте 1 с ≤ x ≤ 1 ч; заполнение
  продлевает TTL, надгробие ставит его заново;
- новых событий и счётчиков нет;
- тест, что кэш используется: без него все тесты выше зелёные и без кэша. Изменить бронь в базе
  мимо API — карточка отдаёт прежнее значение (контракт это разрешает);
- TTL в Redis идёт по реальному времени, фейковые часы его не двигают: если от TTL зависит
  поведение, тест на него — не переводом `app.Clock`;
- `ICacheService` для карточки не используется, поэтому промах `RedisCacheService.GetAsync`
  для значимых типов здесь не нужен.
