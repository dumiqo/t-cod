# 23.3 Гонки и взаимоблокировка

Статус: проработано

- встречные отмены двух клиентов, каждый из которых ждёт на занятии другого: обе `200`,
  без `503`, каждый продвинут на чужое занятие. Детерминированно: тест держит оба абонемента
  (`user_id IN (a, b) FOR UPDATE`), ждёт двух заблокированных и отпускает. Общий запрос
  абонементов введён в 23.1, тест сразу зелёный: красный — временной поломкой (отдельный замок
  своего абонемента даёт взаимоблокировку и `503`), вывод — в отчёт, поломка откатывается;
- отмена с продвижением против ухода из очереди (§8) и против постановки (§7): ушедший места
  не получает, порядок очереди сохраняется. Оба порядка, через замок занятия
  и `WaitForBlockedCountAsync(1)`, затем `(2)`, как в 20.5:
  - отмена первой — запись `promoted`, §8 — `409 already-promoted`; уход первым — §8 `200
    cancelled`, места следующему или свободны;
  - отмена первой — продвинуты прежние ожидающие, новичок `201` в конце очереди или
    `409 seats-available`, если места остались; постановка первой — новичок в конце,
    прежние ожидающие продвинуты раньше него;
- отмена с продвижением против записи (§1) за те же места, оба порядка: мест не больше
  вместимости, посещения за бронь списаны один раз;
- без удержания замка: параллельная пачка отмен, записей и постановок на одно занятие —
  места не больше вместимости, остаток каждого = начальный − списано + возвращено.
