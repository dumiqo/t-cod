# 11. Карточка брони (§4)

Статус: готово (bfd323f)

Без кэша.

- отменённая бронь отдаётся со статусом `cancelled`;
- бронь на отменённом занятии: при `Include(x => x.Class)`, а также при обращении к `x.Class`
  в `Select` или `Where`, фильтр выбрасывает саму бронь;
- чужая бронь → `404`;
- бронь, занятие, зал и абонемент — одним запросом (решение задачи 4): отдельные запросы
  при параллельной отмене смешают бронь до отмены с абонементом после.

Без подзадач, один коммит: метод репозитория сразу появляется одним запросом, и у отдельной
подзадачи «один запрос» не было бы red-фазы.

Решено при разборе (вопросы и ответы до кода):

- админ на чужую бронь тоже получает `404`: роль в контракте важна только для загруженности
  залов. Тест — с токеном `admin001`;
- чтение — `IEnrollmentRepository.GetCardAsync(id, userId)`: один `SELECT` с проекцией,
  `IgnoreQueryFilters()`, владелец в `WHERE` («нет» и «чужая» — одна ветка `null` → `404`),
  `INNER JOIN passes` по `user_id` (навигации к абонементу у брони нет; абонемент есть у каждого
  клиента — по контракту). Без отслеживания и без `TransactionRunner`: чтение ничего
  не блокирует (задача 4). Возвращает record `EnrollmentCard` из `DataAccessLayer` с вложенными
  занятием, залом и абонементом; пометка `// решение:` у запроса — про один запрос;
- «одним запросом» закрепляет тест репозитория на `TestDb.CloneAsync()`: свой
  `DbCommandInterceptor` считает выполненные команды, `GetCardAsync` — ровно одна. Тест зелёный
  с первого прогона: что он ловит регрессию, проверить поломкой (два запроса вместо одного);
- `pass` — текущее состояние абонемента на момент чтения, а не снимок на момент брони. Тест:
  после второй брони карточка первой показывает уменьшенный остаток;
- ответ — новый `EnrollmentCardResponse` с вложенными `class`, `class.room`, `pass`, ровно поля
  контракта. Тест сравнивает JSON целиком: точный набор имён полей на каждом уровне,
  `validUntil` строкой `"2026-09-22"`, `createdAt` и `startsAt` с `Z` до микросекунд и равны
  базе. Этот же тип — ответ §2 (задача 14); где §2 читает карточку, решает задача 14;
- чтение — `EnrollmentService.GetCardAsync(userId, id)` → `EnrollmentCard?`, контроллер отдаёт
  `200` или `NotFound()`. Отдельный сервис под кэш задачи 26 не заводится;
- `EnrollmentStatuses.Cancelled = "cancelled"`; `status` в ответе — значение из базы как есть;
- наблюдаемости нет: чтение не пишет событий и не двигает счётчики (решение задачи 6), `404`
  не логируется;
- `429` — в задаче 28; старт на чистой базе не нужен: схема и старт не меняются;
- тесты эндпоинта — `Enrollments/EnrollmentCardTests.cs`, данные через `TestData`:
  - positive: активная бронь — все поля точно; отменённая — `status: cancelled`, `seats`
    прежний; активная бронь на отменённом занятии — `200`, `class.isCancelled: true`; отменённая
    бронь на отменённом занятии — `200`;
  - negative: `401` без токена; `400` на `abc` и на id больше `long`; `404` на несуществующий
    id, `0`, `-1`, на чужую бронь и на чужую бронь для админа; тела `404` для «нет» и «чужая»
    совпадают, кроме `traceId`;
  - corner: занятие уже началось (`startsAt` равен часам и раньше) — `200`; абонемент просрочен
    вчера, кончается сегодня, остаток `0` — `200` с точными значениями; `seats = int.MaxValue`;
    остаток после второй брони (выше); две брони пользователя на одно занятие — каждая карточка
    отдаёт свою;
- тесты `GetCardAsync` — в `Enrollments/EnrollmentRepositoryTests.cs`: бронь на отменённом
  занятии возвращается (ловушка фильтра), чужая и несуществующая — `null`, ровно одна команда.
  Счётчик — `Infrastructure/CommandCounter.cs` (`DbCommandInterceptor`, все выполненные команды)
  и перегрузка `TestDb.CreateContext(params IInterceptor[])`. Что `AddInterceptors`
  и перехватчик в EF Core 9 работают так — проверить до кода.

Найдено при реализации:

- у репозитория есть только `DbSet<Enrollment>`; набор абонементов для `JOIN` берётся через
  `_dbSet.GetService<ICurrentDbContext>().Context.Set<Pass>()` — навигации и миграции не нужны;
- `IgnoreQueryFilters()` действует на весь запрос, включая `x.Class` в проекции. Проверено поломкой:
  без него 4 теста на отменённое занятие (репозиторий и эндпоинт) красные;
- тест «ровно одна команда» проверен поломкой: лишний `CountAsync` по абонементам →
  `Expected:<1>. Actual:<2>`;
- `System.Text.Json` пишет `DateTime` с `Z` и отбрасывает хвостовые нули дробной части:
  `…:00Z`, `…:00.123456Z`; `DateOnly` — `"2026-09-22"` без настроек;
- нечисловой id в пути (`abc`, `1.5`, больше `long`) — `400` с ключом `id` от `[ApiController]`.
