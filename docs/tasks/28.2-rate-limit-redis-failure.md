# 28.2 Ограничение при отказе Redis

Статус: проработано

Поведение — по решению задачи 24 (заметки, раздел «Отказ Redis»). Начинается после 26.4:
«страж» вызова Redis делается там.

- счётчик в Redis (решение задачи 27): при отказе Redis запрос пропускается, вызов идёт
  через «страж» из 26.4 (предел, фильтр исключений); тест с недоступным Redis — запрос сверх
  лимита проходит;
- тест с «зависшим» Redis — на эндпоинте без кэша (`GET /schedule`), `Redis:OperationTimeout`
  в тесте 200 мс: ответ `200` не позже 200 мс плюс 1 с запаса по секундомеру, событие 1004
  `rate-limit`. Карточка при «зависшем» Redis ждёт оба предела — лимитера и `cache-get`,
  до 2 × `Redis:OperationTimeout`: принято, автомата нет (задача 24);
- событие 1004 Warning и `club.redis.failures` с `operation: rate-limit`, как в 26.4;
  `429` и `club.requests.rejected` при пропуске нет;
- лимитер не повторяет ожидающие надгробия `CardCache`: общий у них только «страж»;
- восстановление: `app.BreakRedis()`, 70 запросов проходят, `app.RestoreRedis()`, 60 проходят,
  61-й — `429`. Пропущенные во время отказа в журнал не попадают (заметки, «За рамками»).
