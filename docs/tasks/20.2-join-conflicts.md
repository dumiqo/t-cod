# 20.2 Причины 409 §7 и границы

Статус: готово (6d6f50b)

- четыре причины, на каждую — тест, что отказ не оставляет следов (очередь, места, остаток);
- `class-cancelled` — занятие читается с `IgnoreQueryFilters()`: без него `404` (ловушка
  из [задачи 20](20-waitlist-join-leave.md), тест переехал сюда из 20.1);
- 6 пар причин по приоритету из задачи 3;
- границы `seats-available`: свободно ровно запрошенное число мест и на одно меньше; отменённые
  брони мест не занимают; `startsAt` равен текущему моменту и на тик позже;
- переполненное занятие (задача 1: свободных мест меньше нуля) — постановка проходит;
- `seats = int.MaxValue` — `201`: проверка мест — `capacity − occupied < seats`, без сложения
  `occupied + seats`, которое переполнит `int` и даст ложный `seats-available`;
- клиент уже стоит с `seats = 2` и просит `seats = 3` — `already-waiting`, запись прежняя,
  места в ней не обновляются;
- у клиента активная бронь на занятии, свободных мест хватает — `seats-available`: «брони
  не мешают» не отменяет правило мест;
- тест репозитория (`TestDb.CloneAsync()`): есть ли своя `waiting` на занятии — своя `cancelled`
  и `promoted`, своя на другом занятии и чужая на этом не считаются;
- `already-waiting`, повторная постановка после ухода и после продвижения, запрос больше
  вместимости, проверка абонемента — по решению задачи 19:
  - `already-waiting` — только при своей записи `waiting` на это занятие; отказ не оставляет
    следов; своя запись `waiting` на другом занятии и чужая на этом не мешают;
  - повторная постановка после ухода — `201`, новый id больше старого, `position` в конце
    очереди; после продвижения (запись `promoted`, есть активная бронь) — тоже `201`;
  - абонемент не проверяется (пометка `// решение:`): просроченный (`validUntil` вчера)
    и с нулём посещений — `201`, остаток посещений прежний;
  - запрос больше вместимости (`seats = capacity + 1`) — `201`, запись в базе (пометка
    `// решение:`).

Нюансы при выполнении:

- без проверки `already-waiting` повторная постановка падает на частичном уникальном индексе
  (`23505` → `500`), а не проходит: это видно в красном прогоне теста `already-waiting`;
- `SumActiveSeatsAsync` возвращает `long`, так что `occupied + seats` тут не переполнился бы,
  но проверка всё равно записана как `capacity − occupied >= seats`, тест `seats = int.MaxValue` её закрепляет.
