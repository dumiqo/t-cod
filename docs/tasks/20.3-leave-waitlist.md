# 20.3 Уход из очереди (§8)

Статус: проработано

- эндпоинт под замком занятия: запись очереди читается по id и владельцу без отслеживания,
  замок занятия, запись перечитывается — как бронь в задаче 12; `cancelled` и `promoted` —
  быстрый путь без замка (в [задаче 20](20-waitlist-join-leave.md)), после замка статус
  проверяется снова;
- перепроверка после замка — тесты здесь, а не в 20.5: без неё уход затирает `promoted`
  на `cancelled` при живой брони. Оба теста держат замок занятия (`HeldLock`), §8 встаёт
  в ожидание (`WaitForBlockedAsync(1)`), затем в той же транзакции (`ExecuteAsync`, `CommitAsync`):
  - запись уходит (`cancelled`) — §8 отвечает `200` тем же телом, `cancelled_at` — от первого
    ухода;
  - запись становится `promoted` и появляется бронь с тем же id — `409 already-promoted`,
    запись и бронь не изменились;
- тест репозитория (`TestDb.CloneAsync()`): своя запись по id без отслеживания — есть; нет
  и чужая — `null` (переехал из 20.1);
- `401`; `400`: нечисловой id, id больше `long` (решение задачи 2); `404`: записи нет, чужая
  запись (и для админа, как в задаче 11), id `0` и отрицательный;
- запись на отменённом занятии: обращение к `e.Class` с фильтром даёт `404` — как в задачах 11
  и 12; уход с отменённого и с начавшегося занятия — по решению задачи 19: оба `200`, запись
  `cancelled`; граница — `startsAt` равен текущему моменту;
- `200` с точным телом; в базе запись `cancelled`, `cancelled_at` — момент ухода. `position`
  в контракте видна только в ответе §7, поэтому «стоявшие за ней поднялись» проверяется так:
  следующий вставший получает позицию на единицу меньше, порядок ожидающих в базе прежний;
- повторный вызов — тот же результат, в базе ничего не меняется: часы сдвигаются между уходами,
  `cancelled_at` остаётся моментом первого ухода, тело совпадает побайтно;
- уход, когда запись уже стала бронью, — по решению задачи 19: `409` с `reason:
  already-promoted` (пометка `// решение:`), запись `promoted` и бронь в базе не изменились;
  так же, если бронь потом отменили. Продвижения ещё нет (задача 23) — тест готовит запись
  `promoted` и бронь с тем же id прямо в базе.
