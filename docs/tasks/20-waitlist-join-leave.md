# 20. Встать в очередь и уйти (§7, §8)

Таблица очереди, позиция, причины отказа, идемпотентность для §7. Отменённое занятие скрыто
фильтром — как в задаче 8: без `IgnoreQueryFilters()` вместо `409 class-cancelled` будет `404`.

Порядок причин — по задаче 3: тест на каждую пару причин (6 пар).

§7 и §8 — под замком занятия (решение задачи 4). Без него постановка может увидеть «мест
не хватает», пока параллельная отмена освобождает места и продвигает очередь без неё, и запись
будет ждать при свободных местах. Ключ идемпотентности §7 — после замка занятия, как в задаче 10.

Порядок очереди: `createdAt`, взятый до ожидания замка, расходится с порядком коммитов. A пришёл
раньше, B первым получил замок и ответ `position: 1`; затем A коммитится с меньшим `createdAt`,
тоже получает `position: 1` и встаёт перед B. Варианты: сортировать по `id` — он выдаётся при
вставке под замком занятия; брать время после замка — это правило уже
действует для всех пишущих запросов (задача 8).

События (задача 6): постановка и уход — `club.waitlist.joined` и `club.waitlist.left`, после
коммита; отказы §7 — `operation = join-waitlist`; повторный уход событий не пишет.

Разбита на подзадачи 20.1–20.6, каждая — свой коммит и своя строка статуса, порядок по номерам.
Схема таблицы и порядок очереди — по решениям задач 18 и 19, идемпотентность — механизм
задачи 10. До 20.1 решить и задачу 21, хотя бы вопрос о свободных местах при непустой очереди:
он меняет смысл `seats-available` в §7, а может вернуть и к проверке `capacity-exceeded` в §1.

## 20.1 Таблица очереди и постановка (§7)

- миграция таблицы очереди (id по решению задачи 18, уникальность по решению задачи 19); сиды
  не меняются; старт на чистой базе — схема меняется;
- id записи в очереди — из последовательности `enrollments.id` (задача 18): id из ответа §7
  не совпадает ни с одной бронью, следующая запись (§1) получает id больше него;
- эндпоинт, транзакция, замок занятия — первое чтение;
- `400` по таблице контракта, в том числе нет заголовка `Idempotency-Key`; `401`; `404`
  занятия нет; отменённое занятие даёт не `404`;
- `201`: тело с точными значениями, `createdAt` усечён до микросекунд; `position` считается
  среди ожидающих; в базе — запись очереди, места и остаток прежние;
- порядок очереди — по решению задачи 19 (варианты — выше).

## 20.2 Причины 409 §7 и границы

- четыре причины, на каждую — тест, что отказ не оставляет следов (очередь, места, остаток);
- 6 пар причин по приоритету из задачи 3;
- границы `seats-available`: свободно ровно запрошенное число мест и на одно меньше; отменённые
  брони мест не занимают; `startsAt` равен текущему моменту и на тик позже;
- переполненное занятие (задача 1: свободных мест меньше нуля) — постановка проходит;
- `already-waiting`, повторная постановка после ухода и после продвижения, запрос больше
  вместимости, проверка абонемента — по решению задачи 19.

## 20.3 Уход из очереди (§8)

- эндпоинт под замком занятия: запись очереди читается по id и владельцу без отслеживания,
  замок занятия, запись перечитывается — как бронь в задаче 12;
- `401`; `400`: нечисловой id, id больше `long` (решение задачи 2); `404`: записи нет, чужая
  запись, id `0` и отрицательный;
- запись на отменённом занятии: обращение к `e.Class` с фильтром даёт `404` — как в задачах 11
  и 12; уход с отменённого и с начавшегося занятия — по решению задачи 19;
- `200` с точным телом; запись в базе ушла из очереди. `position` в контракте видна только
  в ответе §7, поэтому «стоявшие за ней поднялись» проверяется так: следующий вставший получает
  позицию на единицу меньше, порядок ожидающих в базе прежний;
- повторный вызов — тот же результат, в базе ничего не меняется;
- уход, когда запись уже стала бронью, — по решению задачи 19.

## 20.4 Идемпотентность §7

- миграция `idempotency_keys`: колонка `result_position` (nullable, как остальной снимок),
  значение `JoinWaitlist` ↔ `join-waitlist` в `IdempotentOperation` и в `CHECK` по `operation`
  (задача 10 завела их только для `enroll`); юнит-тест сопоставления покрывает новое значение;
- ключ после замка занятия, как в задаче 10; повтор раньше любой причины `409`: повтор
  не получает `already-waiting`;
- на повтор `position` — снимок из первого ответа (решение задачи 9): тест — после постановки
  впереди стоящий уходит, повтор отдаёт прежнюю `position`; так же после продвижения записи;
- тот же ключ, что у записи §1, — не повтор: область ключа — пользователь и операция;
- два одновременных запроса с одним ключом — одна запись в очереди.

## 20.5 Конкурентность и часы

- порядок очереди при замке: тест держит замок занятия, A и B встают в ожидание, ответы
  `position` и порядок в базе совпадают с порядком коммитов;
- две одновременные постановки одного клиента — одна запись, второй `already-waiting`;
- часы после замка: тест держит замок, переводит часы за `startsAt` — `409 class-started`;
- `503` на §7 и §8: записи в очереди не изменились.

## 20.6 Наблюдаемость

- после коммита: `club.waitlist.joined` и `club.waitlist.left` с событиями; повторный уход
  событий не пишет;
- отказы §7 — `operation = join-waitlist`, после отказа нет события постановки;
- тесты 20.4 и 20.5 дополнить, как в 8.4: одно событие постановки на одну запись в очереди,
  у второго — `already-waiting` или повтор.
