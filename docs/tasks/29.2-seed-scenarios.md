# 29.2 Сценарии на сидах

Проверка на данных `DatabaseSeeder`, а не на созданных тестом: то, что увидит проверяющий
на чистой базе.

- сценарии из сидов:
  - занятия с 0, 1 и 2 свободными местами;
  - занятия, которые начнутся через 20–115 минут: фейковые часы стоят на моменте засева
    шаблона (решение задачи 5), поэтому это ровно 20–115 минут по часам теста;
  - занятия с одинаковым временем начала;
  - пользователь с двумя бронями по одному месту на одно занятие;
  - активные брони на отменённых занятиях;
  - абонементы с 0 и 1 посещением и просроченные;
- сиды остаются как есть: тест сначала находит нужное занятие или пользователя запросом
  к базе, а не по захардкоженному id — порядок засева может отличаться между прогонами;
- на каждый сценарий — запрос к своему эндпоинту с точным ответом и состоянием базы после
  (запись на последнее место, `capacity-exceeded` на полном, отмена ближе двух часов,
  карточка брони на отменённом занятии, `pass-exhausted` / `pass-expired`, расписание
  и загруженность с одинаковым временем начала);
- старт приложения на чистой базе (`docker compose down -v`, команды из `README`) —
  критерий готовности, проверяется вручную и записывается в отчёт.
